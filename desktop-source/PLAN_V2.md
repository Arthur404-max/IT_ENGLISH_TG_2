# План v2 — IT English Lab

**Статус: завершено 13.11.2026.**

Критерии приёмки: полностью офлайн-работающая обычная сборка, совместимость с
`progress.json` v1, паритет обычной и embedded-сборок и повторяемые
smoke/E2E-проверки.

## 1. SRS и повторение

- [x] `WordStat` хранит `due_at`, `interval_days`, `ease_factor`, `reviews`,
  `last_ms`; `due_at` — Unix-время в секундах, `0` — «сейчас».
- [x] `box` оставлен для совместимости, но планирование и очередь строятся по
  SRS-полям.
- [x] Правильный ответ: первый интервал 1 день, затем `interval × ease`;
  ease повышается с ограничением. Ошибка: интервал сбрасывается, повтор через
  10 минут, ease понижается.
- [x] `response_ms` принимается API и сохраняется в `last_ms` и статистике
  экзамена.
- [x] Очередь «на сегодня» и дневная цель работают на главной и в тренажёре.
- [x] Ошибки экзамена с `review_en` автоматически попадают в SRS-очередь.
- [x] Никогда не изученные слова не считаются просроченными; флажки экзамена
  включаются в очередь.

## 2. Аналитика

- [x] Разбивка по юнитам и типам заданий.
- [x] Слабые темы и рекомендации по следующему шагу.
- [x] График активности за 30 дней и суммарное время.
- [x] Сравнение двух попыток по результату, времени и разделам.
- [x] CSV-экспорт содержит `item_id`, `time_ms`, тип, юнит и результат.
- [x] Аналитика строится по истории попыток и сохраняется после перезапуска.

## 3. Экзамен

- [x] Карта вопросов с текущим вопросом (`aria-current="step"`).
- [x] Переход к вопросу, кнопка «назад» и сохранение позиции.
- [x] Флажки вопросов с `aria-pressed` и отображением на карте.
- [x] Precheck перед завершением: пропущенные и отмеченные вопросы,
  подтверждение завершения.
- [x] Таймер на экзамен, автосохранение по истечении времени.
- [x] Время на каждое задание и стабильные ID в истории.
- [x] Режимы практики и экзамена, возобновление черновика.

## 4. Сохранность данных

- [x] Атомарное сохранение JSON.
- [x] До пяти резервных копий с миллисекундными именами; сортировка и ротация
  по встроенной метке времени.
- [x] Бэкапы при старте, перед ежедневным сохранением и разрушительными
  действиями.
- [x] Повреждённый JSON переименовывается в `*.corrupt-<ts>.json`, приложение
  стартует безопасно и показывает предупреждение.
- [x] Ошибка записи возвращает HTTP 500 и отражается в `/api/health`
  (`save_error`).
- [x] Схема v2 и автоматическая миграция v1 с сохранением истории и дневной
  статистики.
- [x] Импорт `merge`/`replace` с валидацией известных полей; чужой JSON
  отклоняется.
- [x] Восстановление из проверенного бэкапа; path traversal отклоняется.
- [x] Защита от одновременного запуска двух экземпляров с одной папкой данных.

## 5. PWA и мобильный интерфейс

- [x] Manifest, иконки 192/512, standalone, theme-color.
- [x] Service worker кэширует оболочку; проверено обновление shell-1 → shell-2 →
  shell-3 с удалением старого кэша.
- [x] `viewport-fit=cover`, safe-area отступы, мобильная нижняя навигация.
- [x] Установка из браузера и подсказка, если установка недоступна.
- [x] Проверены размеры 390×844 и 360×800 без горизонтального переполнения.
- [x] Offline-режим: локальный сервер не требует интернета; после остановки
  сервера приложение не обещает сетевые функции.

## 6. Аудирование и speaking

- [x] TTS с нормальной скоростью и 0.75×.
- [x] Shadowing: прослушать, повторить, сверить с транскриптом.
- [x] Транскрипт скрыт по умолчанию.
- [x] Вопросы на понимание после аудирования/текста.
- [x] Элементы банка с тегом `audio`; запись микрофона не обязательна и не

## 7. Доступность

- [x] Skip-link и логичный порядок заголовков на всех основных экранах.

- [x] `aria-expanded` для меню.
- [x] Focus trap, `inert`, `aria-modal`, возврат фокуса в модальных окнах.

## Примечания

- Записанных аудиофайлов нет: аудирование использует TTS и транскрипт.
- PWA-установка на LAN-адресе зависит от secure-context политики браузера;

- Embedded-сборка тяжелее обычной из-за llama.cpp/GGUF; обязательные функции
  доступны и без неё.
