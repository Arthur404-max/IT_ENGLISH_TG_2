# IT English Lab

Локальное приложение для подготовки к экзамену по IT-английскому. Работает как
один exe: запускает локальный HTTP-сервер, открывает браузер и хранит прогресс
на диске. Интернет и AI для основных функций не нужны.

## Возможности

- **15 юнитов**: 312 терминов, 17 текстов, 84 вопроса и 98 заданий на перевод.
- **Экзаменационные Q&A**: 60 вопросов из экзаменационного PDF распределены по
  темам всех 15 юнитов и пронумерованы 1–60. Под каждым вопросом сразу видны
  короткий ответ на английском (уровень A2–B1, до 250 символов) и русский
  перевод. Ответы составлены строго по учебнику
  `ESSENTIAL ENGLISH FOR EXAMS`; если тема в учебнике не раскрыта, ответ прямо
  говорит об этом, а не добавляет факты из интернета.
- **Центр учёбы**: readiness score, дневные лимиты, умная очередь, недельный
  план, слабые юниты и типы заданий в одном экране.
- **FSRS вместо SM-2**: стабильность, сложность, рейтинги Again/Hard/Good/Easy,
  lapse-состояния и прогноз следующего повторения. Цель по памяти (80–95%) и
  максимальный интервал настраиваются без переписывания старых сроков карточек;
  90% сохраняет прежние интервалы. Старые поля прогресса сохранены для
  совместимости.
- **Leech-колода и лимиты**: проблемные слова автоматически отделяются после
  серии забываний; настраиваются лимиты новых слов, повторений, leech и ошибок
  экзамена, желаемое время занятия и дата экзамена.
- **Тетрадь ошибок**: каждая ошибка экзамена получает объяснение, пример и
  мини-дрилл. Отработанные записи сохраняются в `progress.json`.
- **Диагностика**: 20 смешанных заданий за 25 минут в режиме экзамена; результат
  сохраняется отдельной попыткой с `mode: "diagnostic"`.
- **Аудио-библиотека**: 5 локальных WAV-записей (16 кГц, моно) с транскриптом,
  переводом, заданиями, скоростью воспроизведения и отметкой «Прослушано».
  TTS остаётся резервом для остальных текстов курса.
- **Speaking-практика**: 141 фраза и вопрос из всех 15 юнитов, выбор английского
  голоса системного TTS, повтор фразы ×2 для shadowing, запись через
  `MediaRecorder`, прослушивание своей записи, повторные попытки и самооценка.
  Записи остаются в браузере; в прогрессе сохраняются только отметки об
  отработанных фразах и число попыток. При отсутствии TTS есть переход к
  локальным WAV.
- **Тренажёр**: карточки, перевод RU→EN и EN→RU, пропуски, аудирование,
  теневой повтор (shadowing), вопросы на понимание текста.
- **Контекст (cloze)**: предложение берётся из реального текста юнита, целевое
  слово маскируется, ответ проверяется с учётом словоформ; после ответа
  показывается полное предложение и перевод. Режим также входит в смешанную
  тренировку. В умной очереди повторения и leech-колоде контекст включается
  автоматически, если для слова есть предложение; остальные слова остаются
  карточками или набором.
- **Экзамены**: карта вопросов, переход к любому вопросу, флажки, проверка
  перед завершением, предупреждение о пропущенных ответах, таймер и время по
  каждому заданию.
- **Аналитика**: разбивка по юнитам и типам заданий, слабые темы, график
  активности, время, сравнение двух попыток, рекомендации и CSV-экспорт с
  `item_id` и `time_ms`.
- **PWA**: manifest, standalone-режим, service worker `itelab-v4-shell-*`,
  установка из браузера, `viewport-fit=cover` и безопасные отступы на телефонах.
- **Мобильная полировка**: семь разделов в нижней навигации, toast, таймер и
  нижняя навигация не перекрывают друг друга; проверены экраны 360×800 и
  390×844.
- **Доступность**: skip-link, aria-current, aria-expanded, focus trap в
  модальных окнах, возврат фокуса, таймер без ежесекундных объявлений,
  reduced-motion.
- **Данные**: атомарное сохранение, 5 ротационных бэкапов, восстановление,
  карантин повреждённых JSON, импорт с merge/replace и миграция v1→v2→v3.
- **AI — необязательно**: OpenAI-совместимый API или локальная GGUF-модель в
  embedded-сборке. AI помогает с объяснениями и переводом, но не участвует в
  обязательном выставлении оценки и может быть отменён.

## Быстрый старт

1. Запустите `dist\it-english-lab.exe` (обычная сборка).
2. Откроется `http://127.0.0.1:8787` (если порт занят, приложение выберет
   следующий свободный).
3. Прогресс хранится в `%APPDATA%\ITEnglishLab`.

Параметры запуска:

```powershell
# Свой порт и папка данных
.\dist\it-english-lab.exe --port 8899 --data-dir "$env:TEMP\itelab-data"

# Не открывать браузер автоматически
.\dist\it-english-lab.exe --no-open

# Доступ с телефона по локальной сети
.\dist\it-english-lab.exe --lan

# Справка
.\dist\it-english-lab.exe --help
```

`--lan` печатает адрес вида `http://192.168.x.x:8787`. Телефон и компьютер
должны быть в одной Wi-Fi-сети; может потребоваться разрешение в брандмауэре
Windows. PWA-установка и service worker надёжно работают на `localhost`; на
телефоне по LAN-адресу установка зависит от политики браузера (secure context).

Для записи речи с телефона нужен HTTPS: браузер не даёт доступ к микрофону на
обычном HTTP-адресе. При доступе через Tailscale включите HTTPS-прокси на порт
приложения:

```powershell
# Приложение запущено на 8787; команда ниже публикует его по HTTPS в tailnet.
tailscale serve --bg 8787
tailscale serve status
```

Если HTTPS/Serve ещё не включён в tailnet, первая команда выведет ссылку на
админку Tailscale для однократного включения. После этого откройте
`https://<magicdns-имя>/` на телефоне. На компьютере
`http://127.0.0.1:8787` уже считается secure context, и запись работает без
дополнительной настройки.

## Центр учёбы

Экран `#/study` собирает данные из локального прогресса и банка заданий:

- readiness ring с компонентами «Словарь», «Экзамены», «Диагностика» и
  «Регулярность»;
- остатки дневных лимитов и кнопки запуска очередей `review`, `new`, `leech` и
  `exam`;
- план на 7 дней с задачами, минутами и фокусом дня;
- слабые юниты и типы заданий;
- настройки нагрузки и дата экзамена;
- FSRS-персонализация: целевая вероятность вспоминания (80–95%) и максимальный
  интервал. Новые интервалы применяются после ответа, уже назначенные сроки не
  переписываются; 90% эквивалентны расписанию предыдущих версий.

Диагностика запускается из раздела экзаменов. После неё readiness пересчитывается
по фактическому результату, а ошибки попадают в тетрадь ошибок и очередь
повторения.

## Данные и резервные копии

В папке данных находятся:

- `progress.json` — прогресс, FSRS, лимиты, leech, история экзаменов, метаданные
  ответов, отработанные ошибки, прослушанные аудио и speaking-попытки;
- `settings.json` — настройки приложения и AI;
- `backups/` — резервные копии `progress-<millis>.json`.

Сохранение атомарное: сначала пишется временный файл, затем выполняется замена.
Ведётся до пяти последних бэкапов. Копии создаются при старте (если прогресс
успешно прочитан), перед ежедневным сохранением и перед разрушительными
операциями (reset, импорт, восстановление).

Если `progress.json` или `settings.json` повреждён, файл переименовывается в
`*.corrupt-<timestamp>.json`, приложение стартует с безопасным состоянием и
показывает предупреждение. Повреждённый файл не попадает в бэкапы.

Импорт прогресса поддерживает два режима:

- **merge** — добавляет слова, статистику и историю к текущим данным;
- **replace** — полностью заменяет прогресс.

Импортируются только известные поля прогресса; произвольный JSON отклоняется.
Перед импортом и восстановлением создаётся бэкап. Восстановление доступно в
«Настройки → Данные и прогресс» и принимает только проверенные имена файлов из
`backups/`.

Схема прогресса — v3. Старый `progress.json` v1/v2 читается и автоматически
мигрируется: FSRS-поля выводятся из `box`, `interval_days` и `ease_factor`,
история экзаменов и дневная статистика сохраняются. Новые настройки FSRS
(`desired_retention_pct`, `max_interval_days`) получают значения по умолчанию
90% и 3650 дней, поэтому старые файлы не требуют отдельной миграции. Speaking
добавляет необязательные `speaking_done`, `speaking_attempts` и
`speaking_last_at`; в старых файлах они безопасно становятся пустыми/нулевыми.
Старые поля остаются в JSON для совместимости.

Если запись не удалась, API возвращает ошибку, а `/api/health` содержит
`save_error` с описанием проблемы. Одновременно с одной папкой данных может
работать только один экземпляр сервера (файловая блокировка).

## Экзамены и аналитика

Экзамен можно проходить в режиме практики или экзамена. Вопросы можно отмечать
флажком и переходить по карте. Перед завершением показывается precheck:
количество пропущенных и отмеченных вопросов; завершение остаётся возможным,
но требует подтверждения. В историю попадают стабильные `item_id`, теги,
`flagged`, `review_en` и время на каждый вопрос.

Экзаменационные ошибки автоматически добавляются в FSRS-очередь и тетрадь
ошибок. Аналитика строится по сохранённым попыткам, поэтому не зависит от
текущей сессии. CSV содержит по строке на задание и поля `item_id`, `time_ms`,
тип, юнит и результат.

## Аудирование и speaking

- 5 локальных WAV-записей из текстов курса; работают без сети после
  кэширования PWA;
- плеер со скоростью 0.85×, 1×, 1.15× и перемоткой на ±5 секунд;
- транскрипт скрыт по умолчанию, перевод и 2 задания на материал;
- отметка «Прослушано» сохраняется в `progress.json`;
- для остальных текстов используется системный TTS, включая замедленный режим
  0.75×;
- теневой повтор: сначала прослушать, затем повторить фразу;
- вопросы на понимание после текста/аудио.

### Speaking-практика `#/speaking`

- Банк из 141 задания: 51 короткая фраза из текстов и 90 вопросов из заданий
  юнитов. Фразы можно фильтровать по типу и юниту.
- «Образец» и «Медленнее» читают фразу системным TTS, «Повтор ×2» — дважды с
  паузой для теневого повтора. Кнопка «Записать» использует `MediaRecorder`;
  после остановки запись доступна в локальном плеере. «Ещё раз» сохраняет
  попытку и сразу начинает новую запись.
- В баре «Голос образца» можно выбрать английский голос браузера/системы,
  проверить его и увидеть, найден ли `en-US`. Локальные голоса помечены и
  работают без сети. Выбор хранится только в `localStorage` этого браузера
  (`itelab.tts.voice.v1`) и применяется также к озвучиванию текстов и заданий;
  в `progress.json` он не попадает.
- Если TTS или английский голос недоступен, показывается предупреждение и
  ссылка на локальные WAV в `#/audio`; TTS-кнопки при отсутствии поддержки
  отключаются.
- «Получилось» добавляет фразу в `speaking_done`, увеличивает
  `speaking_attempts` и переходит к следующей неотработанной фразе. Запись
  никуда не загружается и не попадает в `progress.json`.
- Статистика показывает размер банка, число отработанных фраз и попыток.
  Схема прогресса остаётся v3: новые поля необязательные, старые файлы
  открываются без миграции.
- Для микрофона нужен secure context: `http://127.0.0.1:8787` на компьютере
  или HTTPS-адрес Tailscale Serve на телефоне.

## AI (опционально)

В настройках можно выбрать:

- OpenAI-совместимый endpoint (Ollama, LM Studio, llama.cpp server, OpenAI,
  OpenRouter, DeepSeek и т. п.);
- встроенную GGUF-модель — только для `it-english-lab-embedded.exe`, если
  сборка выполнена с `-Embedded`.

AI используется для объяснения ошибок и перевода. Запрос можно отменить;
недоступность AI не блокирует тренажёр, экзамен, FSRS и аналитику. Оценка
обязательных заданий выставляется локально и не зависит от ответа модели.

## Сборка

Требования:

- Rust stable (edition 2021), Node.js 22+ — для тестов;
- MinGW-w64 (gcc/g++), LLVM/libclang — для embedded-сборки.

```powershell
# Обычная сборка (без локальной GGUF-модели)
.\build.ps1

# Embedded-сборка с llama.cpp/GGUF
.\build.ps1 -Embedded

# Собрать и сразу запустить
.\build.ps1 -Run
```

Результаты:

- `dist\it-english-lab.exe` — обычная сборка;
- `dist\it-english-lab-embedded.exe` — embedded-сборка.

Перед сборкой остановите запущенный exe: `build.ps1` копирует файл в `dist` и
не сможет заменить занятый файл. Для нестандартных путей можно передать
`-MingwRoot`, `-LlvmRoot` и `-TargetDir`.

## Релиз и обновление

Официальный релиз собирается workflow `.github/workflows/release.yml` по тегу
`vX.Y.Z` или вручную без публикации. Workflow собирает plain и embedded exe,
запускает Rust-тесты и smoke, затем упаковывает файлы скриптом
`tools/release.ps1`:

- `IT-English-Lab-vX.Y.Z.zip` — `it-english-lab.exe`,
  `it-english-lab-embedded.exe`, `README.md`, `RELEASE.txt`, `SHA256SUMS.txt`;
- `IT-English-Lab-vX.Y.Z.zip.sha256` — хэш архива;
- `SHA256SUMS-release.txt` — хэши архива и файлов внутри.

Для официальной подписи в закрытом репозитории должны быть заданы secrets
`WINDOWS_PFX_BASE64` (base64 PFX) и `WINDOWS_PFX_PASSWORD`. Тег без валидной
подписи не публикуется. Ручной запуск без сертификата создаёт только unsigned
artifact для проверки сборки.

Проверка скачанного архива:

```powershell
.\tools\verify_release.ps1 -ZipPath .\IT-English-Lab-v4.0.0.zip
```

Скрипт сверяет SHA-256 архива (из соседнего `.sha256`), все файлы из
`SHA256SUMS.txt` и Authenticode-подписи. Для unsigned dev-сборки нужен явный
`-AllowUnsigned`.

Безопасное обновление только вручную, без доступа приложения к репозиторию:

1. Скачайте архив и `.sha256` из закрытого релиза.
2. Остановите работающий exe.
3. Запустите `.\tools\install_release.ps1 -ZipPath <архив> -InstallDir <папка> -Mode plain`
   (или `embedded`). Скрипт проверит хэши и подпись, сделает резервную копию
   старого exe и не тронет `%APPDATA%\ITEnglishLab`.
4. Запустите новый exe.

Приложение не проверяет GitHub, не хранит токены и не выполняет автообновление.

## Тесты и CI

Smoke-тест проверяет API, PWA-ассеты, миграцию v2→v3, FSRS-персонализацию,
leech, очередь, readiness, план, тетрадь ошибок, аудио, speaking-банк,
сохранение попыток и разметку выбора голоса/TTS, импорт/бэкапы,
восстановление, историю после перезапуска и LAN-режим:

```powershell
node tools/smoke_test.js          # 361 проверка, включая LAN
node tools/smoke_test.js --no-lan # 354 проверки без LAN
```

E2E-тест управляет Microsoft Edge через CDP (Node 22+ и глобальный
`WebSocket`), проверяет центр учёбы, запуск очереди, cloze по реальному тексту и
в умной очереди, аудио, запись и самооценку speaking, выбор голоса и сохранение
настройки TTS, диагностику, тетрадь ошибок, экзамен, карту/флажки/precheck,
fake clock, историю после reload,
мобильные размеры 390×844 и 360×800, отсутствие перекрытий toast/timer/nav,
ARIA/focus trap и PWA-кэш v4:

```powershell
node tools/e2e_test.js
node tools/e2e_test.js --headful
node tools/e2e_test.js --edge "C:\Path\To\msedge.exe"
node tools/e2e_test.js --data-dir "$env:TEMP\itelab-e2e-data"
```

E2E создаёт временный профиль Edge и временную папку данных, а скриншоты
складывает в `%TEMP%\itelab-e2e-*`. `--data-dir` позволяет прогнать сценарий на
копии прогресса; тест изменяет и в конце очищает эту папку, поэтому не
указывайте здесь живой `%APPDATA%\ITEnglishLab`. Оба теста можно запускать без
заранее поднятого сервера: они сами запускают `dist\it-english-lab.exe` на
свободном порту.

Контрольные результаты текущей сборки:

- smoke: **361 / 361** (полный прогон с LAN);
- embedded smoke: **354 / 354** (`--no-lan`);
- E2E: **100 / 100** на чистой базе и **101 / 101** на копии реального прогресса;
- Rust: **10 / 10** unit-тестов;
- Lighthouse accessibility: **100** для home, analytics, settings, exams
  (config/runner/precheck), trainer, unit и chat;
- best-practices и SEO — **100** на проверенных экранах.

Для embedded-сборки можно прогнать smoke с переменной:

```powershell
$env:ITELAB_EXE = "$PWD\dist\it-english-lab-embedded.exe"
node tools/smoke_test.js --no-lan
```

CI в `.github/workflows/ci.yml` на Windows выполняет `cargo fmt --check`,
`cargo check`, `cargo test`, release-сборку, smoke и отдельный Edge E2E-job.
Релизный workflow `.github/workflows/release.yml` дополнительно собирает
embedded-версию на GNU-инструментах, проверяет smoke, упаковывает и проверяет
артефакты, а по тегу публикует только подписанный релиз.

## Структура проекта

```
src/
  main.rs       HTTP API, статические ассеты, запуск сервера
  progress.rs   FSRS, прогресс, лимиты, миграция, merge, история
```

## Если что-то не запускается

- Порт занят? Приложение автоматически пробует следующие порты; точный адрес
  печатается в консоли.
- Данные не сохраняются? Проверьте права на папку данных и `/api/health`:
  поле `save_error` покажет причину.
- Нужен чистый прогресс? Сделайте бэкап и используйте reset в настройках.
- LAN-адрес не открывается? Разрешите приложение в брандмауэре Windows и
  проверьте, что телефон в той же сети.
- Аудио не играет? Убедитесь, что браузер не блокирует звук, и откройте
  материал повторно после первого кэширования PWA.
